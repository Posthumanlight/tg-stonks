# Client

The browser client: one SPA that runs as a mobile web app. Telegram Mini App support is
**postponed until after launch**; the client has no Telegram code for now.
It renders server state and sends intents. It never decides outcomes (CLAUDE.md rule 1).

## Decided
- **Stack:** TypeScript (strict), **Phaser 4** for canvas scenes, **Preact + `@preact/signals`**
  for DOM overlays, Vite 8 and vitest. npm is the package manager.
- **Scenes vs overlays:** maps and combat are Phaser scenes (`#game`). Menus and panels are
  Preact components in `#ui`, a full-screen layer with `pointer-events: none`. Only its
  panels (`.panel`) take input, so the canvas stays touchable everywhere else.
- **Signals are the bridge.** Shared state lives in `src/state/` as signals:
  - Preact components re-render when a signal they read changes.
  - Phaser scenes subscribe with `effect()` and dispose it on scene `SHUTDOWN`.
  - Scenes and components never import each other.
- **i18n:**
  - **Keys:** flat keys in `/locales/{en,ua}.json`.
  - **Functions:** `t(key)` takes a compile-time-checked key. `tKey(key)` takes runtime keys,
    such as content `name_key` values from the server.
  - **Locale:** taken from `navigator.languages`. `uk` maps
    to `ua`; English is the fallback.
  - **Tests:** a vitest test checks that both files have the same keys. A pytest test checks
    that every content `name_key` exists in both.
- **Protocol types** are generated by `npm run gen:protocol` into `src/protocol/index.ts`
  and committed. Never edit that file by hand (see [protocol](protocol.md)).
- **Networking:** every HTTP call goes through `src/net/http.ts` (`request()`: Bearer
  token, one refresh-and-retry on 401, `ApiError {status, reasonKey}`); `src/net/api.ts`
  holds the typed endpoints. Realtime traffic uses one WebSocket (`src/net/ws.ts`, below).
  The page and the API share one origin, and Vite proxies `/api` and `/ws` to uvicorn in dev. Static data (the galaxy)
  carries an `ETag` with `Cache-Control: no-cache`, so the browser's HTTP cache revalidates
  it for free.
- **Production hosting:** FastAPI serves `client/dist` at `/` when the directory exists, so
  there's one origin and no CORS.
- **Screens** (see [architecture › Lobby](architecture.md#lobby)): the `screen` signal
  (`src/state/screen.ts`) drives `boot → login → lobby → galaxy | combat`. Menus are
  Preact overlays; the galaxy and combat screens are Phaser scenes.
  - **Login/register:** forms calling `/api/auth/login` and `/api/auth/register`.
  - **Lobby:** the username, logout, **"Galaxy chart"** (opens `GalaxyScene`) and
    **"Combat demo"** (`POST /api/combats/demo`, then the combat screen).
- **Phaser host** (`src/game/host.ts`): the game is created the first time a canvas
  screen is shown, and hidden with its loop asleep on DOM-only screens. Scenes are
  registered without autostart; each canvas screen has one entry scene (`boot` → galaxy,
  `combat`), and switching screens stops the others. `#game` is unhidden **before** the
  game is created: in `Scale.RESIZE` mode a hidden parent measures 0×0 and the canvas
  stays empty.
- **Shared camera** (`src/scenes/shared/`): `viewport.ts` is the pure camera maths (fit,
  zoom-at-point, clamp, screen→world, nearest point), unit-tested. `camera.ts`
  (`CameraController`) turns pan, pinch, wheel and tap into camera moves and
  `onTap(screen, world)` calls. The galaxy and combat scenes both use it, each with its
  own overlay insets.
- **Auth on the client** (`src/state/auth.ts`):
  - The access token lives **in memory only**, never in `localStorage`. The refresh token
    is an httpOnly cookie the client never sees.
  - On start, the client calls `POST /api/auth/refresh`. Success shows the lobby; failure
    shows login.
  - It refreshes about a minute before expiry. On a `401`, it refreshes once and retries
    once. Concurrent refreshes share one request.
  - `onTokenChange()` hands every new token to the WebSocket, which forwards it as
    `auth.refresh`. The token travels in `hello` and `auth.refresh`, never in the URL
    (see [protocol](protocol.md#websocket)).

## Layout
```
client/
  index.html          #game (Phaser canvas) + #ui (Preact overlay)
  vite.config.ts      Preact plugin, /api + /ws proxy, @locales alias, vitest config
  scripts/gen-protocol.mjs
  src/
    main.tsx          i18n → overlay → Phaser → load data
    net/              http.ts (request wrapper), api.ts (endpoints), ws.ts (WsClient)
    state/            signals: auth, screen, galaxy, combatStore (logic), combat (wiring)
    combat/           pure combat UI logic: interaction.ts (tap → intent, highlights),
                      log.ts (event → log line), fixtures.ts (test data)
    i18n/             t(), locale detection
    game/             config.ts (Phaser config, scene registry), host.ts (show/hide, scenes)
    scenes/           BootScene; shared/ (viewport maths, CameraController);
                      galaxy/ (GalaxyScene, layout, palette); combat/ (CombatScene, palette)
    ui/               App.tsx; screens/ (Login, Lobby, GalaxyOverlay);
                      combat/ (CombatScreen, ActionBar, UnitPanel, CombatLog, …); styles.css
    protocol/         GENERATED
```
Pure logic, such as `scenes/galaxy/layout.ts` and the i18n helpers, sits apart from
Phaser and the DOM. It is unit-tested with vitest in `*.test.ts` files next to the source.

## Galaxy chart (first screen)
- **Data:** it loads `GET /api/world/galaxy` once. `BootScene` waits for the data, then
  starts `GalaxyScene`.
- **Orientation:** in portrait, the chart is rotated 90° so the ellipse's long axis runs
  vertically.
- **Fit:** the chart fits the space between the top bar and the hint line.
- **Drawing:** clusters are faint halos with their names below. Lanes are thin blue lines
  and bridges are amber. Stars are coloured by `colour` and sized by spectral class. Star
  names appear once you zoom in 2.5× past fit.
- **Constant screen size:** line widths, radii and labels are drawn in screen pixels
  (divided by zoom) and redrawn when the zoom changes.
- **Input:**
  - drag to pan (clamped to the chart);
  - pinch or the mouse wheel zooms around the gesture point (fit … 10× fit);
  - a tap within 22 px of a star (a 44 px target) selects it, and a tap on empty space
    clears the selection.
- **Star sheet:** the selected star opens a bottom sheet (name, code, spectral type,
  cluster, lane and bridge counts).

## WebSocket client (`src/net/ws.ts`)
- **One connection per tab.** It opens when the combat screen needs it and closes when the
  screen is left. `WsClient` knows nothing about combat.
- **Handshake:** on open it sends `hello {protocol_version, access_token}`. Requests are
  accepted only after `welcome`. `onWelcome` handlers run after **every** connect and
  reconnect; that's where subscribers re-subscribe.
- **Requests:** `request(type, payload)` adds an `id`. It resolves on `ack`, or rejects
  with `WsError(reasonKey)`:
  - on `error`, with the server's reason key;
  - after 10 s, with `ws.timeout`;
  - when the connection drops, with `ws.disconnected`.

  Pushes go to `on(type, handler)`.
- **Keepalive:** a `ping` every 25 s, because the server drops connections that stay
  silent for 60 s.
- **Close codes:**
  - `4426` sets the status to `outdated`. The UI offers a reload and doesn't reconnect.
  - `4401` refreshes the session, then reconnects at once. If the refresh fails, the
    status becomes `signed_out` and the auth flow shows the login screen.
  - Anything else reconnects with backoff (0.5, 1, 2, 4, 8, then 15 s, plus up to 25 %
    jitter). The backoff resets after a `welcome`.
- **Tests:** the socket factory, token source and timers are injectable. `ws.test.ts`
  drives the client with a fake socket.

## Combat screen (functional minimum)
- **State** lives in two files. `state/combatStore.ts` is a factory over an injected
  transport; `state/combat.ts` wires it to the app's socket.
  - **Signals:** `combatId`, `board`, `view`, `legal`, `log`, `mode`, `inspected`,
    `lastError`, `connection` and `busy`, plus the computed `shownUnit`, `activeUnit` and
    `marks` (highlights).
  - **Snapshots and updates:** `combat.snapshot` sets the board, view and legal.
    `combat.events` replaces the view and legal and appends the events to the log (capped
    at 200).
  - **Ordering by `seq`:** duplicate updates are dropped and overlapping catch-ups are
    trimmed. A gap triggers a re-subscribe with `last_seq`.
  - **No rules on the client** (rule 1). What a player can do comes only from `legal`.
- **Interaction** (`combat/interaction.ts`, pure): the `Mode` is `move` (the default),
  `attack {weapon}` or `ability {ability}`.
  - **Move mode** highlights `legal.moves`: green, or orange when the move provokes an
    opportunity attack.
    - A tap on a destination sends `move {to}`. For big units, any square of the
      destination's footprint counts.
    - A tap on a unit inspects it.
  - **Attack mode** starts from a weapon button. Its targets get a red ring, and tapping
    one sends `attack`.
  - **Ability buttons** cast self abilities at once. Other abilities enter targeting mode:
    valid squares turn blue and valid units get a red ring.
  - **Cancelling:** in attack and ability modes, a tap on empty ground cancels.
  - **Back to move mode:** after any accepted action, and whenever `legal` stops offering
    the chosen option.
- **Scene** (`scenes/combat/CombatScene.ts`): a square is 32 world units.
  - Terrain is drawn once per board.
  - Overlays, highlights and unit tokens are redrawn from the signals. A token shows the
    side colour, the model count and a dot when wounded. The active unit gets a yellow
    ring and the inspected one a white ring.
  - There's no animation yet.
- **Overlay** (`ui/combat/`):
  - **Top bar:** back, the round, the active unit, and a banner while the connection is
    down.
  - **Bottom dock:** the unit panel; the action bar (weapons and abilities with their AP
    cost, Wait, End turn, and the AP and movement left); the last error (`tError`); and
    the battle log.
  - **Battle log:** `combat/log.ts` formats the events, leaving out dice, single hits and
    bookkeeping.
  - **Outcome dialog:** shows the result and returns to the lobby.
- **Resume:** reopening the demo, after leaving or reloading the page, returns the same
  active fight. The subscribe answers with a snapshot.

## Dev workflow
Run these in two terminals, from the repo root and from `client/`:
```
poetry run uvicorn app.main:app --app-dir server --reload
npm run dev            # http://localhost:5173, also on your LAN IP for a real phone
```
- Test at 360×640 in browser device emulation (CLAUDE.md client rules).
- `npm run build` writes `client/dist`. Restart uvicorn and the app is served at
  http://localhost:8000/.
- **Windows:** run npm and vitest from PowerShell, cmd or the VS Code terminal. Git Bash
  with an MSYS working directory (`/d/...`) makes vitest load two copies of itself, and
  every suite fails with "Cannot read properties of undefined (reading 'config')".

## Open questions
- **Telegram Mini App (after launch).** Bring back a platform adapter around
  `telegram-web-app.js` (`ready`/`expand`, header colours, `disableVerticalSwipes`, the
  native back button, `--tg-*` safe-area insets, `language_code` for the locale). Load the
  script `async` so a slow telegram.org can't block the page.
- **Combat animations:** tweens for moves and hits, driven by the events. The view already
  holds the end state.
- **Bundle size:** about 1.4 MB minified (370 KB gzip), mostly Phaser. Should Phaser be
  lazy-loaded behind the overlay, or does a custom Phaser build cut it?
- **High-DPI rendering:** the canvas renders at CSS pixels, which is fine for pixel art, but
  vector chart lines are soft on 3× screens.
- **Routing between screens** (galaxy → cluster → system): a scene stack or a URL hash.
- **Offline/PWA:** not now.
