# Client

The browser client: one SPA that runs as a mobile web app and as a Telegram Mini App.
It renders server state and sends intents. It never decides outcomes (CLAUDE.md rule 1).

## Decided
- **Stack:** TypeScript (strict), **Phaser 4** for canvas scenes, **Preact + `@preact/signals`**
  for DOM overlays, Vite 8 and vitest. npm is the package manager.
- **Scenes vs overlays:** maps and combat are Phaser scenes (`#game`). Menus and panels are
  Preact components in `#ui`, a full-screen layer with `pointer-events: none`. Only its
  panels (`.panel`) take input, so the canvas stays touchable everywhere else.
- **Signals are the bridge.** Shared state lives in `src/state/` as signals:
  - Preact components re-render when a signal they read changes.
  - Phaser scenes subscribe with `effect()` and dispose it on scene `SHUTDOWN`.
  - Scenes and components never import each other.
- **The platform adapter** is `src/platform/telegram.ts`. Telegram's official
  `telegram-web-app.js` is loaded in `index.html` and wrapped in a typed `Platform`. Inside
  Telegram it:
  - calls `ready()` and `expand()`;
  - sets the header and background colours;
  - calls `disableVerticalSwipes()`, so dragging the chart doesn't close the app;
  - exposes the native back button and the raw `initData` (verified server-side later,
    rule 11).

  In a normal browser everything is a no-op. Telegram also sets the `--tg-*` CSS variables
  (theme, safe-area insets) that `styles.css` uses.
- **i18n:**
  - **Keys:** flat keys in `/locales/{en,ua}.json`.
  - **Functions:** `t(key)` takes a compile-time-checked key. `tKey(key)` takes runtime keys,
    such as content `name_key` values from the server.
  - **Locale:** taken from Telegram's `language_code`, then `navigator.languages`. `uk` maps
    to `ua`; English is the fallback.
  - **Tests:** a vitest test checks that both files have the same keys. A pytest test checks
    that every content `name_key` exists in both.
- **Protocol types** are generated by `npm run gen:protocol` into `src/protocol/index.ts`
  and committed. Never edit that file by hand (see [protocol](protocol.md)).
- **Networking:** `src/net/api.ts` holds typed `fetch` wrappers. The page and the API share
  one origin, and Vite proxies `/api` and `/ws` to uvicorn in dev. Static data (the galaxy)
  carries an `ETag` with `Cache-Control: no-cache`, so the browser's HTTP cache revalidates
  it for free.
- **Production hosting:** FastAPI serves `client/dist` at `/` when the directory exists, so
  there's one origin and no CORS.

## Layout
```
client/
  index.html          #game (Phaser canvas) + #ui (Preact overlay), Telegram script
  vite.config.ts      Preact plugin, /api + /ws proxy, @locales alias, vitest config
  scripts/gen-protocol.mjs
  src/
    main.tsx          platform → i18n → overlay → Phaser → load data
    platform/         Telegram adapter
    net/              HTTP (later: WebSocket client)
    state/            signals (galaxy, selection)
    i18n/             t(), locale detection
    game/config.ts    Phaser game config (pixelArt, roundPixels, Scale.RESIZE, 2 touches)
    scenes/           BootScene; galaxy/ (GalaxyScene, pure layout.ts, palette.ts)
    ui/               Preact components + styles.css
    protocol/         GENERATED
```
Pure logic, such as `scenes/galaxy/layout.ts` and the i18n helpers, sits apart from
Phaser and the DOM. It is unit-tested with vitest in `*.test.ts` files next to the source.

## Galaxy chart (first screen)
- **Data:** it loads `GET /api/world/galaxy` once. `BootScene` waits for the data, then
  starts `GalaxyScene`.
- **Orientation:** in portrait, the chart is rotated 90° so the ellipse's long axis runs
  vertically.
- **Fit:** the chart fits the space between the top bar and the hint line.
- **Drawing:** clusters are faint halos with their names below. Lanes are thin blue lines
  and bridges are amber. Stars are coloured by `colour` and sized by spectral class. Star
  names appear once you zoom in 2.5× past fit.
- **Constant screen size:** line widths, radii and labels are drawn in screen pixels
  (divided by zoom) and redrawn when the zoom changes.
- **Input:**
  - drag to pan (clamped to the chart);
  - pinch or the mouse wheel zooms around the gesture point (fit … 10× fit);
  - a tap within 22 px of a star (a 44 px target) selects it, and a tap on empty space
    clears the selection.
- **Star sheet:** the selected star opens a bottom sheet (name, code, spectral type,
  cluster, lane and bridge counts). Telegram's back button closes it.

## Dev workflow
Run these in two terminals, from the repo root and from `client/`:
```
poetry run uvicorn app.main:app --app-dir server --reload
npm run dev            # http://localhost:5173, also on your LAN IP for a real phone
```
- Test at 360×640 in browser device emulation (CLAUDE.md client rules).
- `npm run build` writes `client/dist`. Restart uvicorn and the app is served at
  http://localhost:8000/.
- **Windows:** run npm and vitest from PowerShell, cmd or the VS Code terminal. Git Bash
  with an MSYS working directory (`/d/...`) makes vitest load two copies of itself, and
  every suite fails with "Cannot read properties of undefined (reading 'config')".

### Testing inside Telegram (later)
Telegram needs a public HTTPS URL:
1. Run `cloudflared tunnel --url http://localhost:5173` (a quick tunnel; no account
   needed). Add the tunnel host to `server.allowedHosts` in `vite.config.ts`.
2. In @BotFather, use `/newapp` (or the bot's *Configure Mini App*) and set the tunnel URL.
3. Open the Mini App from the bot. For debugging, use Telegram Desktop or Web with the
   devtools enabled (Telegram's "Debug Mini Apps" setting).

## Open questions
- **Bundle size:** about 1.4 MB minified (370 KB gzip), mostly Phaser. Should Phaser be
  lazy-loaded behind the overlay, or does a custom Phaser build cut it?
- **High-DPI rendering:** the canvas renders at CSS pixels, which is fine for pixel art, but
  vector chart lines are soft on 3× screens.
- **Routing between screens** (galaxy → cluster → system): a scene stack or a URL hash.
- **Offline/PWA:** not now.
